# Three audit fixes after -11

## 1. Shadowsocks authentication snapshots

Pinned sing-shadowsocks v0.2.8 is retained under third_party with its license. AEAD and AEAD2022 multi-user tables are built before atomic publication; each handshake/datagram uses a consistent snapshot. Failed validation retains the previous table. The sing-box adapter carries a stable, non-recycled identity instead of indexing a mutable user slice. User changes are serialized and post-authentication admission checks reject retired generations. Unchanged users keep their identity; repeated adds update instead of duplicating named users.

No wire, password, subscription, panel API, real-IP, device-limit, accounting-direction or spool-format changes. Peak memory during updates includes old and new authentication tables; ordinary authentication adds a snapshot load and short identity check, without a lock held during network reads or routing.

Validation: concurrent AEAD/AEAD2022 table/packet tests under race (3 rounds); retained/revoked/re-added identity and invalid-update tests; real SS and SS2022 AES-128/AES-256 TCP exchanges under user churn with exact per-user accounting; existing SS UDP device/rate/accounting test. Linux blue-green isolated tests passed 10 snapshot rounds and 3 proxy rounds. Test VPS verification is pending connection recovery. A combined macOS integration run observed a separate sing-tun default-interface monitor race after successful protocol assertions; preserved in the internal evidence and not represented as a passing full race gate. No production deployment or release.

## 2. Recoverable panel-driven node rebuilds

Panel rebuilds now retain the applied config until the candidate and users are installed. Rule/certificate preparation precedes shutdown. Successful revocations survive rollback. Drain/save/seal failures resume old admission; later failures clean partial state and rebuild the last applied node. Recovery failures retain explicit pending state and retry on the existing polling task before contacting the panel. Expected core errors no longer panic the process. Core presence checks and idempotent removal support partial cleanup. Reliable journals and accounting generations are retained; partial candidate traffic is captured before removal. Existing connections closed during drain cannot be resurrected and may need client reconnection.

Local fault tests cover drain, save, seal capacity, delete, add-node, partial add-users, failed rollback/retry, retained limiter and revocation. Real HTTP/SS port-collision tests restore the old listener and reconcile 12288 bytes in each direction. Both Linux machines passed five rounds including real proxy recovery. First Linux sampling occurred before the final server Write/count finished; evidence was retained, the assertion now waits up to one second for exactly the same byte totals, and both hosts were rerun successfully. No steady-state proxy hot-path work is added; preparation and rollback cost applies only to configuration changes/failures.

Item 1 test-VPS verification also completed: ten snapshot rounds and three SS/SS2022 proxy rounds passed, with CPU/RSS and user-update benchmark records on both machines. Neither item is deployed to the existing service or pushed/released.

## 3. Acknowledge user ETags only after application

User response decoding now stages its ETag; startup, ordinary synchronization and panel rebuilds commit it only after successful application. Failures invalidate both staged and applied cache state so reverting a panel response cannot conceal partial local changes. Healthy updates remain batched. Successful deletions are recorded before additions; failed additions are compensated, with pending cleanup retained across polls if cleanup also fails. Xray removal checks manager state, allowing retries after an already-completed deletion; partial add errors retain a cleanup handle. Identity comparison uses a UUID/UID/speed tuple instead of concatenated strings. No new panel endpoint, configuration or database migration is required.

Tests: applied/unapplied/empty/no-ETag HTTP responses; partial deletion, partial addition and failed cleanup followed by retry; no reactivation of removed users; no duplicate new users; UID reassignment and comparison collision. Local panel/node/Xray race suites passed. Both Linux hosts passed five rounds of user synchronization, alive-outage and rebuild tests. 10000-user unchanged-snapshot benchmarks (three runs per host) record CPU, RSS and allocations; failure paths may refetch a full list, while committed healthy responses retain 304 caching. No existing configuration, password, subscription, true-IP source, device-limit or accounting direction was changed.
