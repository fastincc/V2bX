# 默认 Vision 基础 splice 修补

默认基础 splice 的共享就绪修补已纳入 -19；本页“活动超时”描述的是后续修补，未包含在已发布的 -19 中。发布不代表已部署节点。`EnableVisionSplice` 与 `AnyTLSAdaptiveQuickACK` 仍默认 false。本修补不发送 Vision 原型能力头，不解除面板的默认 Vision 动态策略排除，不改配置、订阅、真实 IP、设备限制或上报格式。验收及性能边界见 [发布说明](RELEASE-0.4.1-19.md)。

## 原因与适用范围

路由副本曾复制 `CanSpliceCopy=2`，后续 TLS/Vision reader、writer 的就绪更新只写入原对象，导致默认 Vision 下行持续使用用户态缓冲。现在仅对符合条件、没有固定限速的 Linux Vision，以及原有显式原型，共享就绪状态。下行必须等自己的 writer 完成切换。原来的 TLS/传输资格判断不放宽；静态限速默认仍禁止 raw splice；其他协议与平台继续原路径。

基础模式调用独立的 `CopyIngress`：数据通过 socket→kernel pipe→socket 搬运，没有动态配额、固定桶等待、16KiB 配额块或每块诊断统计。上传沿用现有解码/缓冲路径，不宣称新增上传零拷贝。每个基础 copy 使用两个 fd，申请最多1MiB内核管道，实际容量受内核限制；不修改系统参数。

## 计费与退出

默认缓冲路径的 `SizeStatWriter` 在输出写入前计用户下载量。基础 splice 因此在源 socket→pipe 读取成功时追加用户下载与源 transport read 计数；pipe→客户端成功输出时单独追加 transport write 计数。输出失败或撤销时，已经从源消费的字节仍归属于原用户代际，不改成“最终送达才计费”。显式可调速原型已有的成功输出计数语义不在本次变更中调整。

基础路径每次最多读取1MiB；与原缓冲路径相比，失败/取消时可能存在更多已读、已计费但尚未写完的管道字节。这是相同计数边界下的读取粒度差异，不保证同一外部失败时刻产生完全相同的字节数。正常完成的流量必须精确一致。

每次源读取即追加原计数器，长连接不必等断开才上报。可靠快照仍按原实现读取计数、落盘成功后减去已保存值，写入并发增量继续保留。整个 copy 在 `LinkManager` 登记一次；撤销/排空关闭两端并等待最后计数完成，旧代际只有静止且结清后才回收。

管道创建失败或内核不支持 splice 时使用缓冲回退；如果源字节已进入 pipe，先按顺序排出这些已计费字节，不重复计费，再继续读取源。网络错误保留部分成功结果，不能把已消费的 pipe 内容丢弃后直接重读源。

## 活动超时

基础 splice 使用已有分块进度回调刷新活动计时，不再把该路径的配置超时覆盖成 24 小时。只有实际读取或成功输出的正字节数才算活动；空读取、等待可读/可写或定时醒来不延长连接寿命。现有 `connIdle`、`uplinkOnly`、`downlinkOnly` 配置及 Xray 周期检查精度保留：真正空闲的连接按配置结束，上行 TCP 半关闭后仍持续下行的连接继续登记活动。

活动通知与计费分开。源读取仍按原边界追加用户下载计数，成功输出仍仅追加相应运输统计；刷新计时不会重复计费。没有新增用户态数据复制、逐块定时器、每连接协程或每块时间查询，splice 和管道参数不变。性能结论需要相同条件下与 -19 对照，不能由此直接承诺所有环境的吞吐零变化。

该修补仅针对可观测传输进度的默认基础路径。显式可调速原型及原生 `ReadFrom` 分支维持既有超时行为；原型的长配额等待需要独立处理，不能无条件套用基础路径的活动规则。`EnableVisionSplice` 和 `AnyTLSAdaptiveQuickACK` 继续默认关闭。

## 验收要求

- 默认真实 Vision 连接必须到达 Xray `CopyRawConn splice` 转移；测试网关本身的 Go splice 不算节点证明。共享就绪修补以旧 -18 作负对照；活动超时修补以未修改的 -19 作负对照。
- 长连接多周期快照、失败保存重试、实际第二设备拒绝、真实 IP、撤销/排空及尾量，分别验证。
- 验证基础 copy 的源读计数和输出计数在部分失败时有意不同；回退必须保序且不漏不重。
- 静态限速、TLS1.2/不适用传输、显式原型、非 Linux 回归。
- 实际进入默认节点 splice 后发送 TCP FIN，并让下行持续超过 `downlinkOnly`；完整传输应不中断，随后停止活动应按配置关闭。另测 FIN 在进入 splice 前、双向空闲及稀疏活动。HTTP 请求结束或 TLS close_notify 不能代替传输 FIN。
- 性能使用独立非 race 对照：共享就绪修补以 -18 为基线，活动超时修补以 -19 为基线，覆盖单向/双向及多连接。记录吞吐、CPU/GiB、RSS和fd；编译成功与功能通过不代表保速结论。
