# 默认 Vision 基础 splice 修补

本地候选修补，尚未发布或部署。`EnableVisionSplice` 与 `AnyTLSAdaptiveQuickACK` 仍默认 false。本修补不发送 Vision 原型能力头，不解除面板的默认 Vision 动态策略排除，不改配置、订阅、真实 IP、设备限制或上报格式。

## 原因与适用范围

路由副本曾复制 `CanSpliceCopy=2`，后续 TLS/Vision reader、writer 的就绪更新只写入原对象，导致默认 Vision 下行持续使用用户态缓冲。现在仅对符合条件、没有固定限速的 Linux Vision，以及原有显式原型，共享就绪状态。下行必须等自己的 writer 完成切换。原来的 TLS/传输资格判断不放宽；静态限速默认仍禁止 raw splice；其他协议与平台继续原路径。

基础模式调用独立的 `CopyIngress`：数据通过 socket→kernel pipe→socket 搬运，没有动态配额、固定桶等待、16KiB 配额块或每块诊断统计。上传沿用现有解码/缓冲路径，不宣称新增上传零拷贝。每个基础 copy 使用两个 fd，申请最多1MiB内核管道，实际容量受内核限制；不修改系统参数。

## 计费与退出

默认缓冲路径的 `SizeStatWriter` 在输出写入前计用户下载量。基础 splice 因此在源 socket→pipe 读取成功时追加用户下载与源 transport read 计数；pipe→客户端成功输出时单独追加 transport write 计数。输出失败或撤销时，已经从源消费的字节仍归属于原用户代际，不改成“最终送达才计费”。显式可调速原型已有的成功输出计数语义不在本次变更中调整。

基础路径每次最多读取1MiB；与原缓冲路径相比，失败/取消时可能存在更多已读、已计费但尚未写完的管道字节。这是相同计数边界下的读取粒度差异，不保证同一外部失败时刻产生完全相同的字节数。正常完成的流量必须精确一致。

每次源读取即追加原计数器，长连接不必等断开才上报。可靠快照仍按原实现读取计数、落盘成功后减去已保存值，写入并发增量继续保留。整个 copy 在 `LinkManager` 登记一次；撤销/排空关闭两端并等待最后计数完成，旧代际只有静止且结清后才回收。

管道创建失败或内核不支持 splice 时使用缓冲回退；如果源字节已进入 pipe，先按顺序排出这些已计费字节，不重复计费，再继续读取源。网络错误保留部分成功结果，不能把已消费的 pipe 内容丢弃后直接重读源。

## 验收要求

- 默认真实 Vision 连接必须到达 Xray `CopyRawConn splice` 转移；测试网关本身的 Go splice 不算节点证明。旧 -18 用相同默认夹具作负对照。
- 长连接多周期快照、失败保存重试、实际第二设备拒绝、真实 IP、撤销/排空及尾量，分别验证。
- 验证基础 copy 的源读计数和输出计数在部分失败时有意不同；回退必须保序且不漏不重。
- 静态限速、TLS1.2/不适用传输、显式原型、非 Linux 回归。
- 性能使用独立非 race 对照：旧 -18、候选默认和原生 ReadFrom，覆盖单向/双向及多连接。记录吞吐、CPU/GiB、RSS和fd；编译成功与功能通过不代表保速结论。
