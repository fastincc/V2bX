# 动态限速诊断与控制隔离

动态限速的触发、到期和策略拒绝提示使用独立、有界的非阻塞诊断队列。唯一的每节点采样任务和持有节点状态锁的策略更新不再直接执行日志 Hook、格式化或输出写入。

## 行为与兼容

- 动态策略字段、revision、采样窗口、阈值和持续时间不变；到期仍由每秒采样驱动，不是硬实时截止。
- 到期仅撤销临时配额，既有静态限速继续生效。用户授权代次、真实 IP、设备租约及计费计数不变。
- 日志保留原 `uid`、`state`、`reason` 和消息含义，并记录事件发生时间；实际输出可能稍后到达。
- 全进程固定 256 个事件槽，最多一个惰性启动的消费任务。队列满时丢弃动态诊断事件并累计计数；出口恢复且日志级别允许时，报告 `dropped` 与 `dropped_total`。这些数量只指动态诊断，访问审计和计费记录不进入这个队列。
- 队列在进程初始化时分配；64 位验收环境的事件槽内容为 18 KiB，另有通道、控制对象和消费任务开销。队列不随用户数或节点重建增长。
- 任意日志 Writer/Hook 可能无法取消；节点关闭不等待这个进程级任务，进程退出也不保证刷完全部诊断。当前控制状态是判定限速状态的依据，不能依赖诊断日志逐条完整。
- 本补丁仅隔离动态限速诊断。其他模块原有同步日志仍可能受同一个日志出口或锁阻塞；系统卡死或调度长期饥饿也不在此补丁的保证范围内。

不限速数据路径、`Control.Wait`、`Observe`、配额扣减和退款算法不变。未新增配置、面板接口或数据库迁移，`EnableVisionSplice` 与 `AnyTLSAdaptiveQuickACK` 继续默认关闭。

## 回归入口

- `TestDynamicDiagnosticsCannotBlockExpiry`：在独立测试进程阻塞真实 Logrus Writer 或 Hook，验证多用户采样、到期、等待者恢复、设备占用与静态限速保留，以及策略更新、撤销和反复节点重建。该测试可原样在旧代码运行作负对照。
- `TestDynamicDiagnosticQueueBoundedAndRecovery`：队列满、并发丢弃计数、恢复汇总、事件时间、无分配投递及日志过滤。
- `TestDynamicDiagnosticConcurrentStartAndDelivery`：并发启动、投递、已输出与已丢弃事件对账。
- `TestDynamicDiagnosticLevelAndWarningCompatibility`：原警告字段与日志级别语义。

这些测试验证控制隔离与资源边界；正常代理吞吐、CPU、RSS、真实协议计费和设备限制还需与未修改版本独立对照，不能以队列测试代替。
