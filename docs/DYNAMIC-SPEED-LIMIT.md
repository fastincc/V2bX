> -18 发布状态：面板动态限速与 Linux Vision Splice 原型已纳入本版；Vision 原型仍默认关闭，只有节点显式启用且面板放行能力时才支持对应动态策略。下文“本轮”“未发布/未部署”和首轮待测事项属于实现阶段记录；当前兼容性、验收及性能边界以 [发布说明](RELEASE-0.4.1-18.md) 为准。

本地开发候选，尚未发布。接口字段、单位、能力协商和面板工作清单见 [接口约定](DYNAMIC-SPEED-LIMIT-INTERFACE.md)。面板配套和两机联调未完成前，不代表可直接上线。

## 规则和执行

只接受用户接口中的可选 v1 规则，默认缺失即关闭。以节点 tag 和授权代际隔离；同一用户的多连接、TCP/UDP、两个方向共享临时速率。不按套餐剩余额度或计费倍率触发，不跨节点汇总。

原始流量观察与计费计数完全分离。转发路径只追加轻量观察计数；节点共享调度器每秒维护滑动窗口。窗口是 1 秒粒度采样近似，调度迟滞也会影响触发时间，不是严格的硬字节配额。历史窗口归零后释放窗口数组；默认未启用时不启动调度器；曾启用后全部关闭时保留一个休眠调度器，但不运行采样定时器。只扫描已启用策略的用户。同一 tag 的节点对象被替换时会停止旧调度器。窗口数组每个采样槽占 16 字节：60 秒约 960 B、3600 秒约 57,600 B/有流量用户，另有控制句柄和映射开销；大窗口、大用户数需单独容量评估。

触发后限时调速，不因普通同步、重连或持续传输延长处罚。到期开始新窗口；面板关闭即时解除临时规则（生效延迟为既有用户拉取周期）。动态执行上限取静态和临时值中的最小正值，使用独立共享额度，同时保持原有静态令牌桶不变；切换规则不发放额外初始额度。重启清空动态内存状态。

## 既有连接和生命周期

sing 的 TCP/UDP、Xray 普通 dispatcher 路径、独立 Hy2 都在认证时保存可更新的用户控制句柄，因此后续开启/调整/关闭规则无需重建用户或重连。关闭功能的热路径只检查空状态，不创建逐包定时器或 goroutine；为了支持后续热启用，每条连接仍有少量句柄/取消状态开销，不能称为绝对零开销。

动态等待在认证/设备锁之外执行，等待可由连接关闭、截止时间、策略变化或用户撤销取消。小请求和大块发送按有界额度轮流取得令牌；在额度等待过程中取消时退还尚未转发的动态预留额度，不预支未来额度。核心排空关闭的是包含动态等待的最外层生命周期对象，避免关闭了内部计费连接但外层仍在等待。

规则更新独立于认证列表差分，不重建用户、不重置设备租约、不改变计费代际。原有固定 speed_limit 变化仍走已有用户同步路径，本功能不把固定限速修改重新定义为无断线更新。

## 兼容性限制

- 用户已确认第一版排除 **Xray/VLESS Vision 动态限速**。保留其原零拷贝和静态配置，节点拒绝误下发的动态规则并告警；不能显示为已执行。节点重建切换为支持的普通传输后，会解除该不支持标记并重新应用规则。
- 实现覆盖公共传输钩子，不等于每种协议/客户端都已完成真实链路验收。Windows/ARM 编译结果不能代替实机运行。
- 真实 IP/PROXY protocol、设备准入、订阅格式、可靠上报及旧上报的计费方向保持原有语义。动态观察不参与计费提交或批次重放，UDP 分片不重复累计逻辑载荷。
- 本功能不会修复原有 UDP 重组、旧上报失败语义、Windows 可靠队列锁等已知边界。不能把功能验收当作这些问题已经解决。

## 验收与发布边界

需要同时验收关闭、开启未触发、已触发三种状态。不限速性能应与 -17 在同机、同参数下交替比较；记录应用有效吞吐、CPU、RSS、HTTPS 延迟及原始字节对账。限速测试必须保持同一条长连接并观察 0→1→4 Mbps→关闭、自动到期、多连接共享和撤销行为。

本轮只修改 V2bX，面板不在变更范围。真实 DB/Redis、两机 HTTP/完整订阅、Linux/WAN 客户端和生产验证待面板 agent 完成接口后再执行。没有推送、发布或远端部署授权的自动延伸。

## 2026-11-02 本地验收摘要

基线为 -17/5da6193。接口、状态与三核心接入分别提交；最终运行时代码为 9162ea5（后续仅文档/CI 提交）。相关包完整 race、全仓库 vet，以及 Linux amd64、Linux arm64、Linux armv7、Windows amd64 编译通过。编译通过不等于对应系统实机验收。

在 macOS/Apple M4 上，真实回环 AnyTLS、独立 Hy2 TCP 的单/8 流，以及 Hy2 混合分片 UDP 8 流，对比基线、关闭、启用未触发，三次交替样本的吞吐中位数变化约 −0.94%～+1.36%。Xray 普通路径的内部管道对照通过，但不是公网 VLESS 吞吐证明。所有成功的协议样本执行原始流量对账；AnyTLS 验证 PROXY v2 真实 IP、设备限制和审计。

同一长连接 0→1→4 Mbps→关闭、自动到期、用户/节点隔离、静态和动态最小上限、取消/排空/撤销、Hy2 UDP 分片计一次通过。受限 HTTPS 204 本地四路下载负载下，10 Mbps 动态限速 P95 为 38 ms，对照固定限速为 104 ms；8 秒测试 CPU 用时 0.439/0.296 秒，RSS 均约 35 MiB。测试进程同时包含客户端和服务端，不是远端节点独立 CPU 用量，也不能外推公网时延。

性能主体对应转发路径候选 2686b4b；9162ea5 仅在其上追加非法输入校验、旧节点调度器回收及测试，没有改变逐字节转发路径。最终 race/vet/四平台编译针对 9162ea5。初轮 UDP 8 流曾出现约 −4.5% 的中位数差异，最终复测为 −0.73%；保留初轮样本，不承诺所有场景绝对零开销。

微基准（3 次）关闭状态的 Observe+Wait 约 1.26 ns/次，并发 Observe 约 138 ns/次，均为 0 B/op。构造及关闭控制状态的分配量：未启用 336 B/次，已有流量的 60 秒窗口 1432 B/次，3600 秒窗口 65944 B/次。这不是总进程或常驻堆占用，未包含用户映射/连接等开销；大规模用户和长窗口需进一步容量测试。RSS 短时样本不能证明无长期内存增长。
