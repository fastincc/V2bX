# 面板管理动态限速接口（v1，本地候选，未发布）

节点按 `(面板节点 tag, 用户认证代际)` 隔离统计；同一用户在同一节点的 TCP/UDP、多个连接及上传下载共享策略。不是套餐耗尽降速，也不是跨节点总量限制。

**第一版明确不支持 Xray/VLESS Vision 动态限速**（用户已选择优先保速）：不关闭其 Linux 零拷贝，不修改原连接和静态限速。请求同时发送 `X-V2bX-Dynamic-Speed-Limit-Exclude: xray-vless-vision`；面板不能向该路径下发启用规则，不确定核心时应保守排除 Vision 节点。节点识别到 Vision 认证账户时拒绝策略并限频告警，不应在 UI 中显示为已执行。后续支持需要单独零拷贝专项改造及 Linux 验收。

## 用户接口

沿用 `GET /api/v1/server/UniProxy/user` 的现有鉴权。新节点发送 `X-V2bX-Dynamic-Speed-Limit: 1`。面板只向声明支持的节点返回用户对象的可选 `dynamic_speed_limit` 字段。JSON 与 MessagePack 字段与单位完全一致。

```json
{"version":1,"revision":12,"enabled":true,"window_seconds":60,"threshold_bytes":1000000000,"speed_mbps":20,"duration_seconds":300}
```

面板计算套餐继承/用户覆盖后的最终规则；所有有效策略变化递增 revision（包括关闭）。显式关闭发送 `{"version":1,"revision":13,"enabled":false}`。更新规则必须改变用户接口 ETag，并按能力区分缓存响应；不能向旧节点误发新版缓存。

约束：version=1；revision 为正 int64；启用时 window_seconds=1..3600，threshold_bytes=1..2^60，speed_mbps=1..1000000（十进制 Mbps，除 8 得字节每秒），duration_seconds=1..86400。禁止用 0 Mbps 表示封禁。enabled 必须明确为布尔值，缺失/null 不能当作关闭。参数非法或未来版本只拒绝该策略，不能撤销用户。日志不得包含响应正文、凭据或 UUID。

完整 200 响应中省略/null 表示移除策略；304 表示全部保持；网络/解析失败保持上次有效状态。禁止把增量用户列表作为完整列表返回。未知/非法策略保留该用户最后有效规则，新用户无有效规则时保持原有固定限速。

revision 低于已接受值，或相同 revision 却内容不同，均不覆盖已有策略。相同规则反复同步不清空窗口、不延长限速。省略/null 为兼容旧面板的明确移除操作；恢复发送时应使用更高 revision。

## 执行语义

原始计费观察点的上传+下载字节，不乘倍率，不含可靠批次重放。1 秒粒度滑动窗口与检查，属于近似时间窗口；允许检查/调度期间超量，不是硬流量配额。达到阈值即临时限速；限速期间不延长处罚；到期清空窗口开始新统计周期。现有固定上限与临时上限取最小正值。

关闭解除临时策略但保留固定限速、认证和设备信息。窗口/阈值变化重建观察窗口，已触发截止时间不延长。面板失联继续最后有效规则，已触发限制仍按时到期。撤销授权优先。进程重启清空窗口及临时限速，重新拉取后开始统计；v1 不落盘这些状态。订阅、计费接口、可靠队列格式均不变。

面板不必新增实时流量 RPC；数据库/管理 UI 的实现由面板维护 agent 决定。当前仅开发 V2bX 端，两机联调必须在面板配套完成后进行。

## 面板 agent 实施清单

1. 保存套餐默认规则和用户覆盖（继承、关闭、启用三种管理状态），计算每个节点可见用户的最终策略；接口只返回最终策略，不要求节点解释套餐关系。
2. 只有请求带 v1 能力头且不属于排除路径时，才返回扩展。保留既有 id/uuid/speed_limit/device_limit、鉴权、用户筛选与空列表含义。
3. 动态规则使用独立字段；不要临时覆盖原来的 speed_limit，否则旧节点会把它当固定限速，新节点也可能走既有用户替换流程。动态字段的变化必须影响 JSON/MessagePack 内容和 ETag。
4. 禁止用计费倍率后的用量或套餐剩余额度填充 threshold_bytes。节点按同一节点的原始上传+下载观察量执行；不同节点独立触发。
5. 明确关闭时下发更高 revision 的 enabled=false；不要用接口报错/省略整个用户来表达关闭限速。空用户列表仍意味着撤销全部授权。
6. 管理页区分“规则已配置”和“节点已执行”；本版没有增加节点状态回传接口，不能仅凭保存成功就宣称节点已生效。

## 首轮两机联调顺序（尚未执行）

由用户完成蓝绿面板配套后，再授权/安排测试 VPS：先核对磁盘、基线与服务配置备份；使用隔离测试账号与节点验证关闭/开启、JSON/MessagePack、ETag/304、非法规则/接口失联；再验证同一长连接 0→1→4 Mbps→关闭和自动到期、多连接 TCP/UDP 共享、规则重放不延期、撤销/设备拒绝、真实 IP。最后在相同版本和负载下对比不限速吞吐、HTTPS 204 延迟、CPU/RSS，并核对旧/可靠两种上报的原始字节及面板最终计费。不能消费其他节点的共享测试任务或把本机回环结果当作两机/生产结果。

## 兼容与回退

不要求修改节点订阅、现有鉴权、证书、真实 IP/PROXY protocol、设备限制或可靠批次格式；不新增 V2bX 数据库。旧本地 EnableDynamicSpeedLimit 不用来开启面板策略，保留配置可解析并明确警告其旧执行链未启用；面板规则默认为缺失/关闭。

回退到 -17 前，先在面板下发明确关闭并等待新版节点成功同步；然后按既有二进制回滚流程执行。新功能没有磁盘状态要迁移，也不清理可靠队列。旧节点应通过能力协商停止接收新字段；旧版本不会执行面板动态策略，不能把回滚误认为仍有限速保护。源站和生产节点不在本轮变更范围内。
